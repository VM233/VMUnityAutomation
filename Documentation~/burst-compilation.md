# Native Burst recompilation after a managed rebuild

An explicit `asset/refresh` request may set `recompileBurst:true`. The existing durable workspace job first completes its normal C# compilation and assembly reload, then requests recompilation through Unity's integrated Burst compiler and waits for completion. This option requires Unity 6000.6 or newer and an enabled integrated Burst compiler. Omission preserves the existing C#-only contract. It changes neither Burst options nor project assets and does not reopen any Editor window.

The observed failure was a successful managed job following an earlier failed dependent-assembly compile. Scheduled voxel jobs still executed a native DLL older than the changed job layout: the first palette bytes were interpreted as a NativeArray length, and all tree raster outputs were empty. C# diagnostics, reload and source/IL inspection cannot prove native adoption. The operation uses the compiler's recompilation entry point, also used by its native options owner, with one original job identity. Unity alone owns the paired managed/native domain lifecycle. It never changes a job name, rearranges fields to fit stale code, disables Burst, or substitutes managed execution.

Do not use this option in versions 0.6.281 or 0.6.282. Those versions additionally issued a native DomainReload after the managed reload had already completed. Subsequent Play Mode startup crashed with an ECS sorting direct call entering a different compiled function. Version 0.6.283 removes that second domain reset. A crashed Editor must be recovered before validating current scheduled kernels; a completed compiler request alone remains insufficient evidence.

The workspace job owns one native request timestamp, its assembly-domain revision and a completion timestamp. It publishes the request before invoking the native owner, observes completion without reissuing, and fails if a new domain reload interrupts the native phase. A 600-second deadline bounds observation; timeout is a terminal failure, not a retry. Native completion is reported separately from C# error counts. Actual scheduled-kernel regressions remain required for behavior and native adoption acceptance.

No new asset scan, timer, thread, transport, source enumeration, binary copying or cache directory deletion. Persisted timestamps/revision and response fields remain below 1 KiB. Compilation work belongs to Unity's existing native compiler and its registered assembly/entry-point set; this wrapper introduces no additional Cartesian loop or native compilation retry.
