# Compiler diagnostic pagination

Discover the exact `vm_auto_compilation_errors` contract through the official
Unity CLI and VM facade. Its schema and errors are owned by the same Automation
query and native compiler callbacks that produce the result.

Start with offset zero. The default page size is 50; supported sizes are 1 to 200.
`severity` accepts `all`, `error`, or `warning`. The ordinary `entries` page uses
`offset`; `deprecatedWarnings` uses its own `deprecatedOffset`. Each offset counts
matching messages skipped from newest to oldest. Messages within each returned
page are chronological. Counts and totals describe the complete retained product,
including messages outside the current page. Severity affects ordinary entries,
while the obsolete-warning list remains independent.

If a result supplies `nextOffset` or `nextDeprecatedOffset`, continue with those
values and the returned `snapshotRevision`. Once an array is exhausted, use its
total as the offset while advancing the other array to avoid repeating it.
A nonzero offset requires a revision. The
revision persists with diagnostics across domain reload. A new completed
compilation changes it: `compilation_snapshot_changed` requires starting a new
query at offset zero rather than combining pages from different products.

`truncated` means at least one array has older messages to read. It becomes false
when both arrays are exhausted. Offsets beyond an array's total return an empty
page. Diagnostic timestamps retain their full date and round-trip precision.

The native owner retains at most 1000 diagnostics. Overflow or incomplete native
capture returns `compilation_diagnostics_incomplete`; partial retained counts must
not be presented as full compiler counts. A clean compilation after adoption is
required to publish a revisioned product. Workspace compilation summaries also
report capture completeness, independently of whether compiler errors exist.

Unknown fields, nonintegral or out-of-range pagination values, unsupported
severity, and empty or missing continuation revisions return `invalid_arguments`.
The input contract is owned by `VmCompilationDiagnosticQuery`; output contracts
are regenerated by `Documentation~/generate-route-contracts.py`. Focused package
tests publish native callback diagnostics and cover multi-page queries, reload,
new publications, overflow, strict arguments, and the public executor.
